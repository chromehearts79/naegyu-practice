# 인계 점검표 (한 장)

인계하는 분과 새 담당자가 함께 보며 위에서부터 차례로 표시합니다. 자세한 설명은 `docs/담당자_시작_안내.md`(처음 준비)와 `docs/유지보수_안내.md`(평소 일)에 있습니다. 이 저장소는 공개이므로 이 표에 사람 이름이나 메일을 적지 않습니다(GitHub 아이디만).

## 1. 인계 전에 (인계하는 분)

- [ ] 연습에서 고친 것이 실제 저장소에 합쳐져 있다(빠진 곳 알림, 검색 시험 전·후 비교, 스킬 고침)
- [ ] 정보보안담당관 답을 받았다(받기 전에는 "ALIO 보다 먼저 받은 파일 올리기"를 쓰지 않는다)
  - ALIO 공시 전에 받은 내규를 공개 저장소와 Claude 에 넣어도 되는가
  - 내규 원본을 공개 저장소에 두어도 되는가, 정보보안지침 제38조②(민간 클라우드)에 맞는가
- [ ] 오류 신고 창구를 정해 `knowledge/site.json` 의 `feedback` 에 넣었다(인공지능전환관리세칙 제31조①)
- [ ] GitHub 저장소와 Claude 계정을 개인 명의로 둘지 기관 명의로 옮길지 정했다

## 2. 계정과 알림 (새 담당자, 인계하는 분이 옆에서)

- [ ] 외부망 PC 에서 `github.com`, `claude.ai/code` 가 열린다
- [ ] GitHub 초대를 수락했다(쓰기 권한). 정·부 담당 아이디를 저장소 변수 `NAEGYU_ASSIGNEES` 에 넣었다(인계하는 분)
- [ ] 저장소 `Watch` → `All Activity`, 알림 메일이 온다(회사 메일이면 스팸함도 확인)
- [ ] Claude 유료 계정(Pro)으로 `claude.ai/code` 에 들어가 GitHub 를 연결했고, 저장소를 열어 "안녕, 이 저장소에 뭐가 있는지 알려 줘"에 대답이 온다

## 3. 함께 연습 (새로 만든 연습 사본에서. 실제 저장소에서는 하지 않는다)

인계하는 분이 사본에 시험 알림 글과 파일을 준비합니다. 담당자가 직접 Claude 에게 말하고, 인계하는 분은 막힌 곳만 적습니다.

| 연습 | 해 볼 것 | 됐나 | 막힌 곳 |
|---|---|---|---|
| ① 단순 개정 | 알림 글 → "내규 개정 반영" → 5단계 → Pull Request 읽기 → 합치기 | [ ] | |
| ② 계산기가 바뀌는 개정 | 금액·일수가 바뀐 내규. 계산기 숫자를 고쳤다는 설명이 나오는지 | [ ] | |
| ③ 새 내규 또는 직접 올리기 | 분류 코드 묻기, 카드 새로 만들기. 직접 올리기는 1번의 정보보안 답을 받은 뒤에만 | [ ] | |
| ④ 새 판 받기 | 합친 뒤 `Releases` 에서 `naegyu-chatbot-vN.html` 받기, 망연계로 내부망에 옮겨 열어 보기 | [ ] | |
| ⑤ 실패 다루기 | 시험이 빨간색일 때 합치지 않고 그 글을 Claude 에게 보여 주기 | [ ] | |

- [ ] 연습마다 Pull Request 의 "검색 시험 전·후"에서 **새로 틀림 0개**를 확인했다
- [ ] 끝나면 연습 사본을 지웠다

## 4. 인계 뒤 첫 한 달

- [ ] 첫 실제 개정 1~2건은 인계하는 분이 Pull Request 를 같이 읽고 담당자가 합친다
- [ ] 매주 월요일 `매주 확인 기록` 메일이 2주 연속 왔다(안 오면 `docs/유지보수_안내.md` 의 "메일이 안 올 때")
- [ ] 첫 실제 개정에 걸린 시간을 `docs/유지보수_안내.md` 의 "사용 시간과 한도"에 적었다
- [ ] 법령 확인(1년에 한 번) 날짜를 달력에 넣었다(`docs/유지보수_안내.md` 의 "법령 확인")

## 알고 넘기는 것 (아직 안 된 일)

- 인터넷망 게시와 망연계 절차는 사람이 합니다(자동화 안 됨).
- 기관 문서(`reports/governance`)는 제출 여부가 확인되지 않아 고치지 않았습니다. 제출할 때 고칠 곳은 `docs/유지보수_안내.md` 의 "인계 할 일"에 있습니다.
- Claude 가 잘못 고친 카드는 시험이 다 잡지 못합니다. 담당부서 확인이 필요하다고 적힌 점은 꼭 소관부서에 묻습니다.
